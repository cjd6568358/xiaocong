## 零、现在已经能用的（实测确认，不是设想）

| 方式 | 入口 | 状态 |
|---|---|---|
| HTTP REST | `http://192.168.1.1:8080/on` `/off` `/status` `/raw?c=<json>` | ✅ 实测生效 |
| 命令文件 | 追加一行 JSON 到 `/tmp/xc.cmd` | ✅ |
| MQTT 下行 | `{"command":{"switch":1}}` 经假云端下发 | ✅ |
| 多插座自动接管 | 靠「DNS 上游劫持」，**不依赖 MAC/IP** | ✅ 天然支持任意台数 |

**已确认的协议事实**（决定了下面所有方案的上限）：

- 设备**逐键解析** `command`，认识的键立即生效，不认识的键**静默忽略**
  （证据：探针 `{"command":{"switch":1,"upgrade":"..."}}` 里 `switch` 生效、`upgrade` 被无视）
- 设备**从不 SUBSCRIBE**，CONNECT 无 Will topic ⇒ 无法从设备侧学习主题
- 设备**不运行任何局域网服务**：UDP 13078 关闭、5683 静默、24 个 TCP 常见端口全关
  （`docs/09` 用阳性对照严格证伪过，不是"没扫到"）

## 一、远程控制：三条路，按推荐度排

### A. easytier 虚拟局域网 ★ 推荐（基础设施已经在了）

**实测发现**：光猫上已经跑着 easytier ——

```
156 root  /f4610u/armbian/bin/easytier-core_upx -c /f4610u/arm...
et_2_pmog  inet addr:10.0.0.1  Mask:255.255.255.0  UP RUNNING
```

也就是说你**已经有一个跨公网的加密虚拟网**，光猫在里面的地址是 `10.0.0.1`。

**唯一挡路的一点**：ixc-go 的 HTTP 现在只监听 `192.168.1.1:8080`：

```
tcp  0  0  192.168.1.1:8080  0.0.0.0:*  LISTEN  224/ixc-go-arm64_up
```

所以从 easytier 那侧（`10.0.0.x`）访问不到。

**改动**：把启动参数 `-http 192.168.1.1:8080` 改成 `-http :8080`（或 `10.0.0.1:8080`）。
一行的事，之后在任何装了 easytier 的地方 `curl http://10.0.0.1:8080/on` 就能控制。

- 成本：改一个启动参数
- 安全性：**不暴露公网**，流量在 easytier 加密隧道里 ★
- 前提：你的控制端（手机/电脑）也要装 easytier 并加入同一个网络

### B. 公网端口映射（光猫有真公网 IP）

```
ppp0  inet addr:139.227.106.115  P-t-P:139.227.106.1
```

PPPoE 拨号拿到的是**公网 IP**，理论上外网能直接进来。但：

- 需要在 `nat PREROUTING` 加端口映射 + `filter` 放行，而 ZTE 的
  `srvcntrl` / `fwports` / `scdrop` 等链会先吞包，规则必须插到**位置 1**
- 暴露在公网上，**8080 目前完全没有鉴权**（谁都能开你家电灯）
- PPPoE 重播会换 IP，需要 DDNS

⇒ 要用就先给 HTTP 加个 token 鉴权，否则别开。

### C. 云端中转

需要一个外部可达的服务（VPS / 云函数 / 机器人 webhook），由它反过来调光猫。
成本高、依赖外部资源，除非你已经在外面有东西，否则不如 A。

## 二、局域网控制：还能加什么

| 方向 | 说明 | 成本 |
|---|---|---|
| **Home Assistant 集成** | 直接用 `RESTful Switch` 指向 8080，或写个 MQTT 桥。做完就能进 HA 的自动化/仪表盘 | 低（改 YAML） |
| **定时 / 自动化** | 光猫有 `/usr/sbin/crond`（`/etc/crontabs` 为空）。加一行 cron 调 `/on` `/off` 即可做定时开关 | 很低 |
| **服务发现** | 让 ixc-go 广播 mDNS/SSDP，手机 App 自动发现 | 中（要改 Go） |
| **状态实时推送** | 现在只能轮询 `/status`。改成 WebSocket/SSE 推送，状态变更立刻可见 | 中（要改 Go） |
| **语音助手** | 走 HA → 巴法云/小爱/天猫精灵。本质是上面的 HA 集成再往外接 | 取决于平台 |
| **电量 / 功率** | 目前设备只上报 `switch`、`rssi`。是否有功率字段**未验证** —— 值得往 `command` 里试几个键看回显 | 低（试一下） |

**关于"局域网直连插座"**：不要再试了。`docs/09` 已经用阳性对照严格证伪——
固件在稳态下根本不跑局域网服务。**所有局域网控制都必须绕道光猫**（也就是现在的做法）。
唯一没验证的残余：**开机/掉线窗口**里 13078 会不会短暂打开（`lan-port-watch.py` 在蹲守）。

## 三、OTA：诚实结论 + 一个新变量

### 已证伪的部分（`docs/09`，别重复投入）

- 四轮 **210 条** OTA 探针：主题 × 键名 × 值形状全覆盖，**零接受**
- 全部送达并被回显 messageId ⇒ 报文确实进了设备，是"键不对"不是"没收到"
- `reboot_count` 全程稳定 ⇒ 也没走 MQTT 分块 OTA
- App 侧**拿不到固件 URL**（`sdkId` 只是个 int，固件地址全在服务端+固件里）

### 新变量：DNS 上游劫持改变了什么

现在光猫能劫持**任意域名**的解析（`-dns-domains` 可配）。这意味着：

> **一旦知道固件 OTA 时访问哪个域名，就能把它劫到我们自己的服务器，直接喂镜像。**

这把 OTA 从"猜 MQTT 键"变成了"猜域名"——后者是**可观测**的（设备一解析就能在日志里看到）。
但目前设备根本不发起 OTA（原厂云端停服了），所以这条路现在无的放矢。

### 建议路径

**物理刷机做一次，之后全是 OTA。**

1. USB-TTL 读 Flash 拿到固件镜像（`firmware/README.md` 有完整步骤）
2. 静态分析出：OTA 域名、固件格式、有没有签名、MQTT 的 OTA 键名
3. 之后就可以纯 OTA 批量升级你所有插座——**这正好解决"我有不止一个插座"的规模问题**

⚠️ 注意：ESP8266 OTA 要求镜像头合法（magic `0xE9` + 校验），厂商若启用签名会直接拒绝。
先读出来看看，别盲目推。

## 四、★ 多插座：现在有个必须先修的缺陷

**问题**：`/on` `/off` 走的是 `PublishToAll`，**广播给所有在线会话**。

```go
mux.HandleFunc("/on", func(...) {
    handler(`{"command":{"switch":1}}`)   // → PublishToAll(raw)
})
```

你有不止一个插座 ⇒ 一按 `/on`，**所有插座一起开**。这显然不是你要的。

**修复方向**（按 deviceId 精准下发）：

1. 建会话时把 `senderId`（即 deviceID，插座上报 `baseInfo` 里有）记进 session
2. `/status` 改成列出每个设备的 ID + 名字 + 当前状态
3. 新增按设备下发的入口，例如：
   - `/on?id=6587529711423210`
   - `/dev/<id>/on`
4. 保留 `/on`（不带 id）作为"全开"语义，但日志里明确标注是广播

顺带：现在 `/status` 只显示 `192.168.1.11:30757` 这种 IP:port，
多插座时你根本分不清谁是谁——改成显示 deviceId 后可读性会好很多。

## 六、一句话总结

- **远程控制**：改一个监听地址就能走 easytier，成本最低、最安全 ★
- **局域网更多方式**：先接 Home Assistant，性价比最高；定时用 cron
- **OTA**：盲探已死心；**读一次 Flash，之后全 OTA**，这是多插座规模化的关键
- **多插座**：先把 `PublishToAll` 改成按 deviceId 下发，否则会串台
