## 三、★ 为什么 `ghidra_out/` 差点成为惨案

它只有 463 KB，却装着**固件侧协议在 C 层的唯一证据**。里面至少这些还没吃透：

**`libsoftAp.so`（配网）**
`app_step0/1/2`、`create_ecdh_key`、`AES128_CBC_encrypt/decrypt_buffer`、
`startSoftAp`、**`startCoap`**、`softap_callback`、`generate_broadcast`

**`libxcsdk.so`（SDK）**
`cmdExec`、`cmdforward`、`cmdwait`、`polling`、`device_aes_encrypt/decrypt`、
**`generate_getlocalkey`**、`getGenKeyPara`、**`easylinkLoop`**、`broadcast`、
`device2mallocjson`、`XConfigStart/Stop`、`_all_functions.txt`、`_disasm.txt`

其中三个命名直接暗示了**还没走完的方向**（见 §四）：

- `easylinkLoop` → EasyLink 是**另一种配网方式**（广播/组播编码 SSID）
- `generate_getlocalkey` → **localkey**，可能就是局域网加密控制的钥匙
- `cmdExec` / `cmdforward` → 命令执行链路，OTA 键可能藏在这条链上

删了它，这些线索就断在"知道有这个函数、但看不到实现"的状态。

## 五、已经过时 / 被推翻的结论（认知层面清理）

这些留着会误导后续，**比删文件更要紧**：

| # | 旧说法 | 现状 |
|---|---|---|
| 1 | 「按 MAC 在 PREROUTING 铺 DNS 劫持」 | **无效**。nat 只对新建连接首包遍历规则，插座那条流早建好、每 30s 刷新 ⇒ 9 小时 0 命中。已改为劫持 **nat OUTPUT 的 DNS 上游** |
| 2 | 「`-m string` 可按域名匹配」 | 内核没有 `xt_string`；`u32`/`addrtype`/`owner`/`length` 同样没有。可用：`mac` `multiport` `conntrack` `physdev` |
| 3 | 「`-i br0` 可能不对，要试 wlan0/4」 | **br0 是对的**。之前误判因用 `-j ACCEPT` 当计数探针（终止型 target 饿死后面的规则） |
| 4 | 「疑似硬件快转旁路」 | 排除 |
| 5 | 劫持域含 `allin.dns.army` | **误伤**：日志出现 `DNS 劫持 wpad.allin.dns.army`（家里设备在查 wpad.*）。已改为只劫持 `ixiaocong.com` |
| 6 | 「OTA 唯一出路是物理刷机」 | 盲探部分仍成立；但**新增变量**：现在能劫持任意域名，读出 OTA 域名后即可纯 OTA |
| 7 | `deploy.py` | 已被 `ixc-ont.sh` 取代（它注入 user_init.sh 的方式你不要） |
| 8 | `-manage-rules` | 有缺陷：`Refresh()` 开头 `if !r.hairpin { return }`，DNS 规则只在启动时装一次 |
| 9 | `/f4610u/etc/user_init.sh` | **路径错**，真实是 **`/f4610u/user_init.sh`** |
| 10 | 「`/on` 控制插座」 | 多插座时会**广播给所有设备**（`PublishToAll`），必须先修 |
