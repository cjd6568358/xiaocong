## 0. 一句话结论

**协议栈已完整还原，包括 native 层。** 设备控制协议是"薄"的——MQTT + 明文 JSON，
没有任何私有加密、没有按设备分主题的花活，技术上完全可以自建服务端。

配网加密也已还原：**secp256k1 ECDH + AES-128-CBC**（IV 硬编码 `abcdefghijklmnop`），
且 `domain`/`crt` 确认会随配网下发给设备。详见 [03-配网与native.md](03-配网与native.md)。

> ### ⚠️ 更正（2026-10-02 真机结论）：报文会下发 ≠ 固件会采用
>
> 「`domain`/`crt` 会随配网下发」只是**报文侧**的事实，当初据此推断
> "免拆机重定向路线成立"。**真机一测，两条路都堵死：**
>
> | 路 | 真机结果 |
> |---|---|
> | `crt` 非空 | 设备**整包拒绝**（重发 `ch_pubk`），连 WiFi 配置都不应用 |
> | `domain` = 公网 IP | 设备**接受配置**，但随后仍去查内置的 `iot.ixiaocong.com` → **被忽略** |
>
> ⇒ **真正的可行路线是劫持固件内置域名（路径 E）**，不是"让设备主动指向我们"。
> 见 [05-免拆机方案.md §11 / §12](05-免拆机方案.md)。

**APK 已重打包并签名** → `build/xiaocong-fixed.apk`。

**已解决**：2026-10-01 22:32 抓包拿到域名 `iot.ixiaocong.com`（现已 NXDOMAIN），

## 3. 业务逻辑全景

App 功能远超一个插座所需，说明厂商在做 IoT 平台：

- **用户**：手机验证码登录 / 微信登录 / 二维码授权登录 / 账号绑定
- **家庭**：多家庭（home）、房间分组（group）、设备移动
- **设备**：绑定 / 解绑 / 重命名 / 置顶 / 参数管理 / 快照 / 网关与子设备（Zigbee）
- **配网**：SoftAP（旧，广播）/ xconfig（新）/ easylink（未实现）
- **控制**：MQTT 实时控制，参数化（`command: {参数key: 值}`）
- **自动化**：IFTTT（触发条件 → 动作）、场景（scene）、设备联动（relation/switch）
- **语音**：通过第三方（小米 / 天猫 / 小度）接入
- **分享**：设备分享给其他用户
- **摄像头**：Aoni 品牌，云存储 / 直播 / 回放 / 订单 / 支付（增值业务）
- **其他**：电量统计、天气、门锁（mensuo）、红外（infrared）、商城（有赞 youzan）
- **推送**：腾讯 TPNS / 小米 / 华为 / 魅族 / 信鸽

**结论**：协议层是按"通用 IoT 平台"设计的，设备控制只是其中一小块。

## 4. 三条关键链路

### 4.1 配网链路（SoftAP）

```
长按 5s → 插座开热点 smart-<产品号>-<MAC后6位>-<校验码>
        ↓ 校验码 = 前段 SSID 字节和 & 0xFF 的十六进制
手机连上 192.168.4.1 的热点
        ↓
App 每 4.5s 向 192.168.4.255:5658 广播：
   {"type":"ch_pubk","pubkey":"<base64 公钥 64B>"}        ← native，明文 JSON
        ↓ 设备以 ch_pubk 回应 → secp256k1 ECDH → AES key（共享密钥低 16B）
AES-128-CBC 加密后 base64 发送 ch_data：                  ← native
   {"type":"ch_data","ssid":..,"password":..,"clientId":..,
    "checkCode":..,"domain":..,"crt":..}   ← IV 硬编码 "abcdefghijklmnop"
        ↓ 设备回 {"mac":..,"product_id":..} → 再发 {"type":"end"}
插座连上家里 WiFi，App 切回家庭网络
        ↓ 每 2.5s CoAP 探测（UDP 13078，Uri-Path="Scan"）/ 每 3s HTTP getDiscovered
发现设备 → device/getBindInfo → device/bind（云绑定）
```

细节（含 C 伪代码）见 [03-配网与native.md](03-配网与native.md)。

Java 层函数签名：

```java
native startSoftAp(String broadAddress, String ssid, String password,
                   String domain,   // ★ 原厂传 ""，改此可重定向到自建服务器
                   String crt,      // ★ 原厂传 ""
                   String clientId, String checkCode)
native startCoap(String addr, String productId, String mac)
```

### 4.2 控制链路（MQTT）

```
App → MQTT broker (ssl://<host>:<port>, 证书固定 test.crt)
  publish topic "control":
  {"messageId":<9位随机>,"protocolVersion":"1.0.0",
   "receiveId":"<设备ID>","senderId":"<clientId>",
   "command":{"1":1}}                       ← 1=开, 0=关

设备 → topic "snapshot":
  {"code":0,"messageId":...,"protocolVersion":"1.0.0",
   "receiveId":"<clientId>","senderId":"<设备ID>",
   "status":1,"snapshot":{"1":1}}
```

- **5 个主题**：`control` `manage`（下行）/ `snapshot` `online` `offline` `error`（上行）
- **路由靠 payload 里的 `receiveId`，不靠主题**
- **订阅是服务端绑定的**：App 里没有 `subscribe()` 调用，
  只调 HTTP `device/subscribe/all`，由服务端给客户端绑定
- **无任何加密**（TLS 之外），纯 UTF-8 JSON，QoS 0

详见 [02-MQTT协议.md](02-MQTT协议.md)。

### 4.3 OTA / 固件升级

- `device/sdk/check` / `device/sdk/detail` / `device/sdk/upgrade`
- 固件包从服务端下发，**随厂商停服而失效**

### 4.4 局域网控制（CoAP）

`libxcsdk.so` 提供一套 **CoAP over UDP 13078** 的局域网通道：

```
GET Uri-Path="Scan"    {"scanType":N,"productId":"..."}   发现设备
GET Uri-Path="Getkey"  {"Query":"1"}                      取局域网密钥
cmdExec 2=Scan / 3=GetLocalKey / 4=Snapshot / 5=Control
```

⚠️ 但在 App 里它**只用于配网期发现设备**，稳态控制仍走云端 MQTT。
固件稳态是否也监听 13078 → 待真机 `nmap -sU -p 13078`。
